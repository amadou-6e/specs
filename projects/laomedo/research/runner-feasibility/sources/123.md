# Trace completeness across Laomedo's upstream systems, issue #123

Status: **partial evidence; no-go for a complete cross-provider trace claim**,
2026-09-30. This is a zero-incremental-model-spend investigation for
[issue #123](https://github.com/amadou-6e/specs/issues/123). It measures
recorded behavior against the proposed [run-traces contract](../../../subsystems/run-traces/contract/README.md)
and [shared component contract](../../../architecture/shared-contracts.md). It does not build
a production monitoring UI.

The reproducible projection and import probes, tests, and sanitized native
call/result ID pairs are in the
[Laomedo #123 experiment](https://github.com/amadou-6e/laomedo/tree/2230f22/experiments/feasibility/123),
at [commit `2230f22`](https://github.com/amadou-6e/laomedo/commit/2230f22)
and under review in [Laomedo PR #7](https://github.com/amadou-6e/laomedo/pull/7).
The actual Codex sample comes from the #146 synthetic Docker run; its
underlying private rollout and the persistent login remain outside Git. No
new model turn or credential copy was made for this issue.

The Langflow `totalTokens: 0` is a measured **outer span value**, not a
measurement of the nested Codex run. Treating it as total agent usage would
misstate the run. The absence of a Claude sample is **unknown**, not zero.
No observed Codex event proves that a selected skill file was read merely
because it was offered; usage needs a source read/invocation event or stays
unknown.

## Import and event-handling checks

The private #146 Codex rollout had 50 JSONL records: one `session_meta`, 21
`event_msg`, 18 `response_item`, two `world_state`, two `turn_context`, and six
`token_usage_record` entries. AGENTVIZ detected Codex and returned 14 display
events in two turns, including four tool calls with four attached outputs.
Its metadata retained the native session ID; the events retained both turn
IDs, all four tool-call IDs, and native response-item IDs under
`raw.payload.id`. It reported zero malformed or invalid events. This checks
successful import and selected ID preservation, not one-to-one raw-event
coverage or a UI review of the displayed trace.

The #123 projection prototype consumes already sanitized event envelopes.
Seven focused tests passed: duplicate IDs, conflicting ID reuse,
result-before-call order, equal
timestamps, incomplete interruption, unknown versus zero usage, stable
reprojection, source-scoped IDs, and a sanitizer that rejects arbitrary
content. This is **synthetic evidence only** for reconnect, cancellation,
and parser change behavior. No provider reconnect or interrupted private
trace was replayed through AGENTVIZ. Raw provider payloads must remain
append-only and independently available for later reprojection.

## Minimum normalized record and correlation

The proposed minimum is `run_id`, `sequence`, `received_ordinal`, `source`,
`source_event_id`, `source_time`, `observed_at`, `kind`, a raw-payload reference plus digest,
`provenance`, and source-specific native session and call IDs. A run registry
must separately bind Langflow invocation/component IDs, `AgentRunSpec`,
source/effective/post-run workspace refs, requested/effective model and
effort, and a terminal status. A tool result links by an explicit call ID;
equal timestamps do not establish identity or order. Duplicate source event
IDs with identical payload digests can be ignored during projection while the
immutable raw log retains both receipts; a conflicting duplicate must fail.
A Codex item ID shared by started and completed notifications is a call-link
ID, not a unique event ID. Missing event IDs remain null and cannot be
manufactured from time or message text.

Store capability separately from value. `unknown`, `unsupported`, `omitted`,
and a measured `0` are distinct states. A failed or interrupted run may keep
messages, tool output, and a partial diff while `trace_complete` is false.
Reprojection may change display events; it must not rewrite source records,
run identity, or raw-payload digests. The prototype demonstrates these rules
only on synthetic envelopes.

## Decision and next evidence

**Go** for a narrow local experiment that imports a private Codex rollout
into AGENTVIZ while Laomedo stores raw events separately. **No-go** for the
complete Codex/Claude/Langflow monitoring claim on current evidence. The
next comparative run needs #121's supported CLI and dedicated credential,
an equivalent disposable task, structured Langflow-to-Laomedo IDs, and
provider interruption/reconnect samples. #123 authorizes zero incremental
model spend; any new model-backed comparison needs a separately authorized
budget. This report can feed [#124](https://github.com/amadou-6e/specs/issues/124)
with explicit unknowns rather than delaying its synthesis indefinitely.

Prompts, command content, files, and raw tool output were not committed.
Access-control, retention, and production redaction policies belong to #124's
risk assessment and later implementation design.
