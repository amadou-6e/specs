# Claude runner isolation, persistence, and settings: initial findings

Status: **no-go for the proposed local MVP on current evidence**, 2026-09-30.
This publishes the verified
probe design, the pinned SDK, and first observed environment evidence for
[specs issue #121](https://github.com/amadou-6e/specs/issues/121). The
credentialed probes have not been executed; they require a native Claude Code
CLI and a dedicated credential.

The [Claude Agent component](../../../subsystems/agent-execution/contract/claude.md) defines the
proposed flow step; [runner isolation](../../../subsystems/agent-execution/contract/isolation.md) and
[run traces](../../../subsystems/run-traces/contract/README.md) specify shared execution boundaries.
The spike code is at
[`laomedo/experiments/feasibility/121/`](https://github.com/amadou-6e/laomedo/tree/docs/121/experiments/feasibility/121)
and open for review in a Laomedo PR.

## Relationship to #119 and #118

#119 documented Claude skill paths but did not test them: no Claude executable
or dedicated credential was available. This spike reproduces that blocker at
the SDK layer with precise evidence (below) and designs the isolation and
settings probes so they can run as soon as a CLI and credential exist. #118's
environment guidance is implemented: `CLAUDE_CONFIG_DIR` must point at a
private directory because global configuration is read regardless of
`setting_sources`; auto memory is disabled with
`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`; and because the SDK's `env` option merges
with the parent environment, the harness overrides every personal-profile and
provider-redirecting variable explicitly.

## Observed: the SDK blocker is precise

`probe_environment.py` ran without a credential on 2026-09-29. The installed
distribution is a pure-Python wheel, which cannot carry a platform binary, so
the SDK found no bundled CLI; its resolution then searches for a native
executable, and none is installed. Session start therefore fails with
`CLINotFoundError` before any authentication or model call. The error message
names the remedies: install the native CLI
(`irm https://claude.ai/install.ps1 | iex`), use a wheel that bundles the CLI
for the platform, or pass `cli_path` explicitly. The probe also confirmed the
private config directory is created and all personal root hashes were
unchanged.

This is the #119 blocker reproduced at the SDK layer, with the failure surface
identified precisely enough to unblock: install a native `claude.exe`.

## Protocol facts the probes rely on

Verified against the SDK 0.2.161 reference and confirmed by import:

- Skill discovery is governed by `setting_sources` (`user`, `project`,
  `local`; `[]` disables all). Skills load from `~/.claude/skills/`,
  `<cwd>/.claude/skills/`, and `.claude/skills/` in parents up to the
  repository root. `add_dirs` extends project-skill discovery.
- The `system/init` message (`SystemMessage.data`) reports the session ID,
  model, and the `skills` array of user-invocable skills plus bundled skills.
  The array lists discovered skills whether or not they are in the `skills`
  allowlist. `data["slash_commands"]` lists the command surface.
- `skills` accepts exact names or `"all"`; malformed names are rejected with
  `ValueError` before the CLI starts. Dispatch by `/<name>` works regardless
  of the allowlist, and an unlisted skill's files stay reachable through Read;
  the probes verify both behaviors.
- Model and effort support is model-specific. Per the
  [model configuration reference](https://code.claude.com/docs/en/model-config#adjust-effort-level),
  Fable 5.x, Opus 5.x/4.7/4.8, and Sonnet 5.x support `low` through `max`;
  Opus 4.6 and Sonnet 4.6 support `low` through `max` without `xhigh`; models
  not listed do not support effort. The reference documents a silent
  fallback: a level the model does not support runs at the highest supported
  level at or below it ("`xhigh` runs as `high` on Opus 4.6"). The
  [`EffortLevel` type](https://code.claude.com/docs/en/agent-sdk/python#effortlevel)
  is `low | medium | high | xhigh | max`.
- Effective model is visible per response (`AssistantMessage.model`) and per
  run (`ResultMessage.model_usage` keys); cost is `ResultMessage.total_cost_usd`.
  Effective effort has no observed field in the message stream; the probes
  record it as unknown rather than inferring it.
- Streaming yields `ToolUseBlock` (id, name, input) and matching
  `ToolResultBlock` (tool_use_id, content, is_error). Failures surface as
  `ResultMessage` subtypes (`error_during_execution`, `error_max_turns`,
  `error_max_budget_usd`, ...) and `ResultError`; cancellation via
  `client.interrupt()` ends with `terminal_reason` `aborted_streaming` or
  `aborted_tools`.
- Resume is by session ID (`resume=`); each `query()` spawns a fresh CLI
  process, so resume across processes is the restart test. `fork_session`
  creates a distinct session ID. Sessions can also be listed and read via
  `list_sessions()` / `get_session_info()` / `get_session_messages()`.

## Credential gate and spend

The gate accepts only a dedicated `ANTHROPIC_API_KEY` with the `sk-ant-api`
prefix from the runner environment; subscription OAuth tokens also start with
`sk-ant-` and are refused. It refuses a state dir inside a git
working tree, a missing or malformed key, any provider-redirecting variable
set in the parent environment (`ANTHROPIC_AUTH_TOKEN`,
`CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_BASE_URL`, the Bedrock/Vertex/Foundry
switches, and the model-selection variables), an OAuth token file in the
private config dir, unreachable `api.anthropic.com`, or an unavailable Claude
CLI before any budget reservation. The forced-invalid key used by the
environment probe cannot bill. The `sk-ant-api` prefix verifies format only;
dedicated provenance still needs an operator check.

USD 20 is the issue cap. Both probes now require the same existing private
`--budget-dir` outside Git, with distinct new or empty child state directories.
A persistent ledger reserves each call before submission and stops after 16
calls or when reserved/observed exposure would reach USD 20. The planned
per-call `max_budget_usd` ceilings sum to USD 12.75 (7 settings calls at
$0.25, 8 stream calls at $1.25, and one cancellation call at $1.00). Unknown
cost retains its full reservation. This is a conservative local stop, not a
hard provider cap: `max_budget_usd` is checked between turns, so one turn
can exceed its ceiling. A strict USD 20 bound needs a provider-side budget.
`ResultMessage.total_cost_usd` is recorded when available, and the call is
counted at submission.

## Workspace snapshot scope limit

The SDK persists conversation history only; session transcripts live under
`$CLAUDE_CONFIG_DIR/projects/<encoded-cwd>/<session-id>.jsonl`. The stream
probe now copies the exact post-run workspace into private state, introduces
drift, verifies that a missing snapshot is rejected before modification,
restores the snapshot, checks its hash, and only then resumes the native
session in a fresh query process. This is a spike-level runner guard, not an
SDK workspace feature or production snapshot registry. Continuity also
requires a synthetic marker (`LAOMEDO-121-READY`) to return in run 2 with no
Read call; a re-read is reported separately and does not count as continuity.
Resuming an unknown session ID is the SDK-level explicit failure the probe
tests. These are implemented test paths, not yet observed pass results.

## Remaining

- Execute both credentialed probes only when a native `claude.exe` and a
  dedicated key are available; fill the currently unknown pass-condition
  matrix before reconsidering this no-go decision.
- Verify the dedicated credential's provenance outside the probe. Its
  `sk-ant-api` prefix is only a format check, not proof of a dedicated account.
- Record `system/init` data keys verbatim on the pinned version, including the
  `skills` array and `slash_commands`, and any field absent from the
  reference.
- Record which candidate user-skill root the runner version actually reads
  (home versus `CLAUDE_CONFIG_DIR`), which #119 could not resolve for Codex
  either.
- Record the effort fallback empirically for the unsupported pair, and any
  effective-effort evidence (for example, CLI debug stderr signals).
- Record any gap against `AgentRunSpec`: effort is an option rather than a
  validated dispatch parameter with documented silent fallback, and there is
  no native workspace-snapshot concept to verify before resume.

## Go/no-go

**No-go on current evidence for the proposed local Claude MVP.** The native
CLI was unavailable and no dedicated credential was supplied, so the probe
stopped before a model call as issue #121 required. All five model-backed pass
conditions remain unknown; none is claimed to have failed in Claude itself.
The code and environment blocker are reviewable, but they do not establish
isolation, resume, event coverage, or effective settings. Reconsider only
after all five conditions are exercised with a supported CLI and credential.
