# Skill Draft editing boundary: bounded feasibility result

Status: **allowed Codex edit and resume demonstrated; full boundary still partial**, 2026-09-30. This addresses
[issue #122](https://github.com/amadou-6e/specs/issues/122) using the #119
skill-discovery baseline and #120's private Codex runner. The sanitized proof
and reproduction commands are in
[`laomedo/experiments/feasibility/122/`](https://github.com/amadou-6e/laomedo/tree/docs/122/experiments/feasibility/122).
The final proof is in [Laomedo commit `4b9e7d3`](https://github.com/amadou-6e/laomedo/commit/4b9e7d3)
and [PR #4](https://github.com/amadou-6e/laomedo/pull/4).
Five of the permitted six Codex turns were submitted. No canonical skill was
modified or promoted.

## Policy and draft record

The spike uses a separate `edit-policy.json` with policy ID
`fixture-edit-policy-122`, revision `1`, and canonical JSON hash
`sha256:0d0c67179033c5948276b3fe32f8e3e222f9995f3b5fb59b62f4a4ae0d6c4c14`.
It allows `SKILL.md` and `examples/amber.md`, Markdown only, at most two
files of 8,192 bytes each. Scripts, dependencies, and assets are forbidden.
It requires `name` and `description` frontmatter and permits only the
`structural-v1` and `fixed-case-v1` deterministic checks. The policy hash is
recorded beside each draft, separate from the skill's consumer instructions.

The synthetic base skill tree hash is
`sha256:b56c33d7112ea9b76ce82f7c4295082dbef6385274f5673dfac2dfd63c8ee2cf`.
An allowed synthetic edit produced a different draft hash, changed-path list,
unified patch, structural validation, and a base/draft fixed-case comparison.
Its synthetic `agent_run_id` and `trace_ref` are null. This is deterministic
validation of a proposed draft, not an agent run or model-judged quality score.

## Predeclared pass conditions

| Condition | Result | Limit |
| --- | --- | --- |
| Canonical skill tree unchanged | Pass for synthetic cases and the first five turns; turn 6 used a separate empty fixture | The personal session-root comparison remains confounded by concurrent IDE use |
| Allowed agent edit yields pinned draft, patch, validation and trace | Pass in turn 4 | The draft was not promoted; model-based quality was not claimed |
| Forbidden paths and escaping links blocked | Partial | Validator rejects forbidden paths and junctions; a direct-command elevated sandbox denied a sibling-store write. Native symlink creation was denied on this host. The agent-originated attempt timed out before a tool item |
| Resume uses the last post-run draft | Pass in turn 5 | Missing snapshot refusal, hash-verified restore, same native thread, and retention of the first example were observed |
| Concurrent base change blocks promotion | Pass in deterministic fixture | Revision mismatch marks the proposal ineligible; promotion itself is not implemented |

The harness also preserves the partial patch after a synthetic exception or
timeout and marks both drafts ineligible. These are injected failures, not
observed agent crashes or timeouts. The fixed-case evaluation checks only
whether the amber rule remains in the file. It does not measure future model
behavior.

## Model-backed observations

The #120 file-backed ChatGPT credential was reused from its existing
access-restricted private Codex profile. No new login or auth copy was made.
The #122 runs, raw app-server traces, and separate six-turn ledger remained
outside Git. All six submitted turns requested `gpt-6-luna` at low effort.
The recorded turn contexts match. The personal skill and auth hashes stayed
stable; changes to the personal session-root hash remain confounded by
concurrent IDE use.

Turns 1 and 2 completed without tool items or file changes. The first turn
recorded a read-only policy. The second recorded a workspace-write turn
policy, yet its shell read and patch were denied. Private stderr logs identify
tool-router denials, including a patch rejected as outside the project under
the runner's `approvalPolicy: never`. A separate `command/exec` canary could
write to the draft, but that direct command did not prove the agent's own
tools had permission. The pinned alpha CLI and a credential-free check of
CLI 0.159.0 returned `readOnly` at `thread/start` without an explicit Windows
sandbox mode. The pinned generated schema uses `workspace-write` for
`thread/start.sandbox` and `workspaceWrite` for `turn/start.sandboxPolicy`;
the [current app-server reference](https://learn.chatgpt.com/docs/app-server)
shows a different thread-start spelling. Record the installed schema rather
than treating a successful direct command as an agent grant.

Turn 3 used CLI 0.159.0 with an explicit per-process elevated Windows sandbox
outside the calling tool's restricted context. It returned `workspaceWrite`
and streamed completed command and file-change items. The agent appended the
requested example to `SKILL.md` and left the canonical skill unchanged.
Validation rejected the full draft because PowerShell created a literal
`%SystemDrive%/ProgramData/Microsoft/Windows/Caches/` tree in it. The reported
`skill_missing` was a consequence of inventory discarding the whole invalid
tree; the edited file was present. A temporary clean copy of that file passed
structural validation and the fixed case. A credential-free elevated
PowerShell read reproduced the cache tree when the runner's clean environment
omitted `SystemDrive` and avoided it when the drive was supplied. Turn 3 was
not resumed or promoted.

The runner then added `SystemDrive` derived from `SystemRoot` to its private
environment. Turn 4 produced a valid draft through observed command and
file-change items. The draft had one changed file, a patch, no validation
violations, and a passing fixed case. The runner froze its post-run hash,
injected a disposable drift file, refused a missing snapshot without a
change, and restored the frozen hash. After app-server restart, turn 5
resumed the same native thread. Its snapshot contained the first example
only; the final draft retained that example and added the second. It again
contained only `SKILL.md`, passed structural validation and the fixed case,
and was marked promotion eligible. No promotion was performed.

A credential-free direct-command probe found that, without an explicit
Windows sandbox mode, both read-only and sibling-store write restrictions
failed. With [elevated native Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)
outside the calling tool sandbox, a draft write succeeded while read-only
and sibling-store writes were denied. This is evidence for a direct-command
filesystem boundary, not an agent-originated forbidden-write test or network
isolation. The third through fifth turns changed CLI version, Windows mode,
and calling-tool context together, so they do not isolate which change
resolved each original tool-router denial.

The five turns reported cumulative input/cached/output totals, with zero
cache-write tokens reported: turn 1: 27,885/24,064/109; turn 2:
123,486/85,760/324; turn 3: 58,045/50,176/457; turn 4:
42,960/39,168/223. The resumed thread reported 86,943/81,408/436 after
turn 5, so its incremental usage was 43,983/42,240/213. Applying the
[GPT-6 Luna Standard short-context API rates](https://developers.openai.com/api/docs/models/gpt-6-luna)
of USD 0.10 per million uncached input, 0.01 cached input, and 0.50 output
gives about **USD 0.00857 API-equivalent usage** across all five turns.
This assumes Standard processing; it is not an actual ChatGPT subscription
charge. Sanitized IDs, hashes, usage, and
event counts are in the Laomedo `observations.json`; raw traces are private.

The credential-free loopback network probe started a local synthetic HTTP
fixture and requested `command/exec` under elevated Windows sandbox. Its
first, network-enabled command timed out twice, including with a 90-second
response wait. The network-disabled command was therefore not reached. No
network allow or deny result was observed. This is not a network isolation
pass or failure.

The final forbidden-write probe reused the existing private profile. Its
first credential-free direct-command preflight timed out, without reserving
a model turn. A second attempt used the earlier successful elevated
direct-command boundary result as its preflight. It started a native
`workspaceWrite` thread and submitted turn 6 against a synthetic sibling
store. The agent's first message said it would attempt the single write,
but the 120-second turn wait timed out with no command or file-change item.
The forbidden target was absent and the sentinel hash unchanged. Since the
trace does not show an attempted tool call, it cannot demonstrate that an
agent-originated forbidden write was denied. The turn ledger is now 6/6;
the final usage update is partial. Its observed API-equivalent lower-bound
increment is about USD 0.00186, bringing the six-turn observed lower bound
to about USD 0.01043 under the same rate assumptions.

Three protected elevated-sandbox scratch directories remain in the ignored
AGENTVIZ `probe-artifacts.local/` directory, inside its checkout but ignored
by Git. Exact-path
recursive cleanup was attempted, but Windows denied access to each
`sandbox_users.json` file even from the elevated tool context. An
administrator cleanup route is still needed; no protected file content was
opened or committed.

## Minimum enforcement boundary and next proof

The validated local route uses an explicit elevated Windows sandbox, a private
profile, a clean environment with `SystemDrive` supplied, a disposable draft
root, observed agent tool calls, post-run tree validation, and a hash-bound
snapshot for resume. Direct-command evidence shows that the elevated sandbox
can deny writes outside the draft; the Python validator separately rejects
unapproved content before promotion. Neither a natural-language edit
instruction nor a successful in-draft canary alone proves confinement. The
runner must fail closed if the effective permission grant or draft inventory
differs from what was requested.

The next proof must capture an agent-originated forbidden write and the
resulting tool denial, but it needs a new explicitly approved turn budget.
Native symlink creation was unavailable on this host, so escaping-link
evidence remains limited to validator and Windows junction checks. Network
isolation remains unverified after the loopback timeout. Production work
also needs an explicit promotion operation that compares the current canonical
revision and tree hash with the pinned base and aborts on conflict. #121's
Claude runner still has no matching edit result. This is a **go for a bounded
Codex Skill Draft prototype**, with these enforcement checks open before a
production or cross-provider claim.
