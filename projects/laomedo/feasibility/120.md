# Codex runner isolation, persistence, and settings: bounded findings

Status: bounded local run completed, 2026-09-29. This publishes corrected
probes and sanitized results for [specs issue #120](https://github.com/amadou-6e/specs/issues/120).
Three submitted ChatGPT-backed turns used the approved cap. Condition 4 did not
pass, and personal-session isolation remains inconclusive, so this is a no-go
for the proposed local MVP on the current evidence.

The [Codex Agent component](../components/codex-agent.md) defines the proposed
flow step; [runner isolation](../sandboxing/runner-isolation.md) and
[run traces](../monitoring/run-traces.md) specify shared execution boundaries.
The spike code is at
[`laomedo/experiments/feasibility/120/`](https://github.com/amadou-6e/laomedo/tree/docs/120/experiments/feasibility/120)
and open for review in Laomedo PR [#2](https://github.com/amadou-6e/laomedo/pull/2).

## Relationship to #119

## Protocol notes from the app-server reference

The first probe draft misread the protocol. The corrected probes follow the
[official app-server reference](https://learn.chatgpt.com/docs/app-server):

- Resume uses the dedicated `thread/resume` method with `threadId`;
  `thread/start` has no `threadId` parameter.
- The effective `model`, `reasoningEffort`, `sandbox`, and `approvalPolicy` are
  top-level fields of the `thread/start` result, not fields of the returned
  thread object. The probes read the result level and record which key sets
  were present so a different runner version cannot be misread.
- A `turn/start` response carries no effort field; its `Turn` object holds id,
  items, status, and timing. The credentialed probes now inspect the matching
  private rollout file's `turn_context` record for effective effort. All three
  completed turns had matching model and effort values in that record.
- Stream item types are `commandExecution`, `fileChange`, `mcpToolCall`,
  `dynamicToolCall`, and others. There is no `toolCall` or `toolResult` item;
  each item carries its own call and result fields (for example,
  `commandExecution` carries `command`, `aggregatedOutput`, `exitCode`, and
  `status`). A result is counted only when the same item ID has both a started
  event and a terminal completed event with an actual result value.
- Reasoning effort is the typed `turn/start` field `effort`, not a
  `thread/start` config override.
- On the pinned CLI, direct `thread/start` with an unknown model and
  `turn/start` with invalid effort `superultra` were both initially accepted
  without a credential. The runner now validates against `model/list` before
  dispatch. The corrected no-model probe rejected an unknown model, an
  invalid effort, and `gpt-6-luna` with unsupported `ultra` effort locally;
  it sent no `turn/start` and made zero model calls.
- `thread/start`, `thread/resume`, and `thread/fork` return
  `instructionSources`, the loaded instruction-file paths. The isolation probe
  uses this to check for a leaked personal `AGENTS.md`. The returned thread
  also carries `cliVersion`, recorded next to `codex --version` so the version
  that actually served the thread is visible.

## Temporary ChatGPT handoff and turn limit

The user chose to keep using the current ChatGPT login for single-user local
feasibility work and defer a proper authentication flow to #129. The issue
rule was explicitly updated before the one-time handoff and bounded turns.

The spike's one-time provisioner copies only the file-backed personal
`auth.json` into a persistent, access-restricted private state directory
outside every Git working tree. It refuses to overwrite an existing private
copy. The probes construct a clean child environment and reuse this private
profile across runs. Their gate requires ChatGPT mode and credential-free
reachability to `chatgpt.com:443`. This follows the [official Codex automation
guidance](https://learn.chatgpt.com/docs/non-interactive-mode) to persist the
runner's refreshed auth file rather than repeatedly seeding it.

This does not establish independent credential identity. Refreshing the
private copy can invalidate the original interactive login; the experiment
did not test whether this occurred. The personal profile must still show no
file writes, skill loads, or new sessions. Do not use the private profile for
a multi-user or hosted runner. An API-key option remains available but is not
required for this temporary local spike.

The probes prefer an advertised `gpt-6-luna` low-effort pair and share a
persistent maximum of three submitted turns. A timeout consumes a turn. All
three turns have been used. With ChatGPT auth, token usage and API-equivalent
cost are reported separately from any actual provider charge. The USD 20 cap
applies if the API-key option is used.

## Workspace snapshot scope limit

Condition 3 as written in #120 is about resuming from the runner's last
post-run workspace snapshot. Codex does not know about Laomedo snapshots.
The updated probe required a completed first turn, copied and hashed the
post-run disposable project, introduced a synthetic drift file, restored the
snapshot, checked the restored hash, and only then called `thread/resume` after
restarting app-server. A unit test verified missing-snapshot refusal happens
before changing the project. This tests the guard in the spike, not a
production runner registry. Native restart/resume succeeded for this one run.

## Remaining: native vs final-response bridge comparison

Analysis only; no remote environment is provisioned or tested. True
remote-only persistence would need a separate host holding the runner profile,
credential, workspace snapshots, native sessions, and raw trace. The client
could retain flow definitions and UI metadata but must not launch Codex or
store native sessions locally. The existing bridge proves only a final-response
call through the Codex Python SDK using the user's default profile. This spike
observed private native thread persistence and a streamed assistant response.
It did not observe a tool item, so the full trace improvement over the bridge
remains unproven.

## Go/no-go

**No-go on current evidence.** Conditions 1, 3, and 5 passed in this bounded
spike. Condition 2 remains inconclusive because the personal sessions root
changed during concurrent IDE activity, though no probe thread appeared
there. Condition 4 failed to demonstrate a matching tool call and result: the
model returned the skill marker without invoking a tool. The three-turn cap
is exhausted. A follow-up with fresh, predeclared turns must isolate the
session comparison and force a tool-capable fixture before reconsidering the
Codex Agent MVP. No production runner or remote environment was built.
