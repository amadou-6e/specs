# Claude runner isolation, persistence, and settings: initial findings

Status: investigation in progress, 2026-09-29. This publishes the verified
probe design, the pinned SDK, and first observed environment evidence for
[specs issue #121](https://github.com/amadou-6e/specs/issues/121). The
credentialed probes have not been executed; they require a native Claude Code
CLI and a dedicated credential.

The [Claude Agent component](../components/claude-agent.md) defines the
proposed flow step; [runner isolation](../sandboxing/runner-isolation.md) and
[run traces](../monitoring/run-traces.md) specify shared execution boundaries.
The spike code is at
[`laomedo/experiments/feasibility/121/`](https://github.com/amadou-6e/laomedo/tree/docs/121/experiments/feasibility/121)
and open for review in a Laomedo PR.

## Relationship to #119

#119 documented Claude skill paths but did not test them: no Claude executable
or dedicated credential was available. This spike reproduces that blocker at
the SDK layer with precise evidence (below) and designs the isolation and
settings probes so they can run as soon as a CLI and credential exist.

## Observed: the SDK blocker is precise

`probe_environment.py` ran without a credential on 2026-09-29. The SDK resolves
its CLI from a bundled binary first, then a native executable. On this machine
the PyPI wheel ships no bundled CLI and no native `claude.exe` is installed,
so session start fails with `CLINotFoundError` before any authentication or
model call. The error message names the three remedies: install the native
CLI (`irm https://claude.ai/install.ps1 | iex`), use a wheel that bundles it,
or pass `cli_path` explicitly. The probe also confirmed the private config
directory is created and all six personal root hashes were unchanged.

This is the #119 blocker reproduced at the SDK layer, with the failure surface
identified precisely enough to unblock: install a native `claude.exe`.

## Protocol facts the probes rely on

Verified against the SDK 0.2.161 reference and confirmed by import:

- Skill discovery is governed by `setting_sources` (`user`, `project`,
  `local`; `[]` disables all). Skills load from `~/.claude/skills/`,
  `<cwd>/.claude/skills/`, and `.claude/skills/` in parents up to the
  repository root. `add_dirs` extends project-skill discovery.
- The `system/init` message (`SystemMessage.data`) reports the session ID,
  model, and the `skills` array of user-invocable skills plus bundled skills.
  The array lists discovered skills whether or not they are in the `skills`
  allowlist. `data["slash_commands"]` lists the command surface.
- `skills` accepts exact names or `"all"`; malformed names are rejected with
  `ValueError` before the CLI starts. Dispatch by `/<name>` works regardless
  of the allowlist.
- Model and effort are typed options; `EffortLevel` is
  `low | medium | high | xhigh | max`. The reference documents that `xhigh`
  falls back to `high` on models that do not support it: a documented silent
  fallback the runner must account for when recording effective effort.
- Effective model is visible per response (`AssistantMessage.model`) and per
  run (`ResultMessage.model_usage` keys); cost is `ResultMessage.total_cost_usd`.
- Streaming yields `ToolUseBlock` (id, name, input) and matching
  `ToolResultBlock` (tool_use_id, content, is_error). Failures surface as
  `ResultMessage` subtypes (`error_during_execution`, `error_max_turns`,
  `error_max_budget_usd`, ...) and `ResultError`; cancellation via
  `client.interrupt()` ends with `terminal_reason` `aborted_streaming` or
  `aborted_tools`.
- Resume is by session ID (`resume=`); each `query()` spawns a fresh CLI
  process, so resume across processes is the restart test. `fork_session`
  creates a distinct session ID. Sessions can also be listed and read via
  `list_sessions()` / `get_session_info()` / `get_session_messages()`.

## Credential gate and spend

The gate accepts only a dedicated `ANTHROPIC_API_KEY` from the runner
environment, rejects a state dir inside a git working tree, rejects a personal
OAuth token file in the private config dir (a copied login), and requires
reachability of `api.anthropic.com`. The forced-invalid key used by the
environment probe cannot bill.

USD 20 is the cap from issue #121. Under an API-key credential,
`ResultMessage.total_cost_usd` is real provider spend; the probes sum it into
`observed_cost_usd` and count a turn on submission as an upper bound on
billable calls. Every credentialed call is bounded by `max_turns=1..3` and
`max_budget_usd` per call.

## Workspace snapshot scope limit

The SDK persists conversation history only; session transcripts live under
`$CLAUDE_CONFIG_DIR/projects/<encoded-cwd>/<session-id>.jsonl`. Restoring the
last post-run workspace snapshot before a resume is the Laomedo runner
registry's responsibility. `probe_stream_resume.py` fingerprints the workspace
before and after each run and reports `workspace_changed` rather than claiming
SDK-provided workspace persistence. Resuming an unknown session ID is the
SDK-level explicit failure the probe can demonstrate.
