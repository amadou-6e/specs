# Laomedo feasibility decision, issue #124

Later evidence, 2026-10-01: the
[implemented Langflow-to-Codex pilot](../implementation/local-skill-agent-pilot.md)
passed the bounded four-turn local test. This dated synthesis remains the
historical feasibility decision; its pending-pilot statements and estimates
are not current implementation status. Permission redesign and AGENTVIZ are
deferred; the newer evidence does not establish Claude parity or hosted use.

Status: **conditional go for a bounded, single-user local Codex pilot; no-go
for the proposed dual-provider or hosted product on current evidence**,
2026-09-30. This is a decision report for
[#124](https://github.com/amadou-6e/specs/issues/124), not an approved
implementation roadmap or a production security assessment. It evaluates the
[agent and skill component proposal](../components/agent-and-skill-components.md)
against the predeclared spike conditions and their observed limits. No new
model call, credential, or GitHub issue edit was used for this synthesis.

## Capability decision matrix

Here **verified** is a completed local observation, **failed** is a tested
condition that did not hold, **unsupported** is an upstream feature absent
from the inspected interface, and **unknown** is not adequately tested.

| Capability | Status | Consequence for the first pilot |
| --- | --- | --- |
| Langflow can call an external agent step | Verified in #118's fixed APIRequest fixture | Reuse its canvas, but replace the bridge with a typed custom component only after the runner contract is fixed. |
| Built-in Langflow Skill node | Unsupported in the inspected Langflow 1.12.3 interface in #118 | Build a thin skill-reference component; keep exact revisions in Laomedo's registry. |
| Existing bridge isolates sessions and skills | Failed in #118 | Do not build on that bridge or its profile assumptions. |
| Native, exact skill subset delivery | Unknown | Start with a pinned whole-skill bundle; store rule/example selections as explicit Laomedo records, not a claimed native skill read. |
| Codex model/effort and same-thread restart resume | Verified in #120; Docker resume rechecked in #146 | Adapt the app-server protocol behind a version-pinned runner. The runner, not Codex, owns workspace snapshot binding. |
| Codex native tool call and result visibility | Failed to demonstrate in #120; verified for a different Docker fixture in #146 | Record source CLI version and task with every trace. Require a matching call/result acceptance test on the pilot version. |
| Canonical skill and forbidden-write protection | Verified on #146's tested Docker mounts and synthetic paths | Use both Docker mount restrictions and Codex's Linux command sandbox, then validate a separate candidate before any promotion. This is not a general hosted security proof. |
| Agent-command network isolation | Verified only for #146's selected loopback/external paths; native Windows route failed a loopback check | Keep the local prototype explicitly bounded. Broader protocol and hosting checks are required before untrusted or hosted use. |
| Credential isolation and lifecycle | Exact-path denial and no personal mount verified in #146; lifecycle unknown | Reuse the temporary private ChatGPT handoff only for bounded local work. #129 must replace it before hosted/multi-user use. |
| Claude model/effort, skill, resume, and streamed events | Unknown because #121 stopped before a call | Defer the Claude adapter and any parity claim until a supported CLI, dedicated credential, and licensing review exist. |
| AGENTVIZ private Codex rollout import | Verified for one #146 synthetic rollout in #123 | Reuse the parser for local inspection; store the raw runner events separately and preserve IDs/provenance. |
| Unified Langflow-to-agent trace and inner usage | Failed in #118's existing fixture: IDs only in output text and outer `totalTokens: 0` despite Codex usage | Build structured correlation and separate outer/inner usage fields. Do not label missing inner usage as zero. |
| Remote-only session persistence | Unknown; no remote runner was provisioned | A Docker volume on the user's machine is private local storage, not remote-only persistence. |

## Build, extend, reuse, or defer

| Subsystem | Recommendation | Reason and boundary |
| --- | --- | --- |
| Flow design | **Extend Langflow** with a thin custom Codex node and later a skill-reference node | Its canvas and component API exist. The node must call a separate Laomedo runner and return structured IDs, not contain the only session or trace. The custom component itself remains untested. |
| Agent execution and persistence | **Build a separate local runner service; adapt Codex app-server** | #120 and #146 prove native thread control, but Laomedo must construct the environment, retain a persistent runner profile, bind snapshots to sessions, enforce timeouts and grants, and store traces. Keep the Docker image/runtime pinned. |
| Skill Revision and Draft | **Build the registry and review boundary** | Upstream skill discovery is not a revision registry. #122's deterministic core and #146's validated candidate are useful starts; a selected rule/example materializer and separately reviewed promotion still need implementation and evaluation. |
| Trace store and correlation | **Build Laomedo raw-event intake and projection; reuse AGENTVIZ inspection where it fits** | AGENTVIZ parsed one Codex rollout, while Langflow's outer span missed inner usage. Preserve raw records, native IDs, provenance, and unknown states; do not make the display projection the evidence store. |
| Claude adapter | **Defer** | #121 has no credentialed trace or runtime acceptance result. Obtain a supported credential and CLI, then test parity. Specialist review of bundled Claude Code CLI Commercial Terms is required before redistribution or hosted use. |
| Deep Agents | **Defer** | #118 found it uses LangChain model runtimes rather than the required Codex or Claude Code agents; it is a reference design, not a drop-in substitute. |
| Production authentication | **Defer to #129 before any hosted use** | The temporary ChatGPT file handoff can refresh or invalidate another copy and provides no tenant identity, rotation, revocation, or robust credential boundary. |

The upstream AGENTVIZ and Langflow licenses were recorded as MIT in #118;
the inspected Codex SDK and CLI packages were Apache-2.0. Those findings do
not resolve Claude Code CLI Commercial Terms, lfx package-metadata ambiguity,
or permissions for a hosted, multi-user runner. Seek specialist license review
before packaging or offering that product.

## Smallest end-to-end pilot contract

Freeze one source workspace hash, one whole-skill `SkillSnapshotRef`, one
`AgentRunSpec` with a supported Codex model/effort pair, a named local Docker
grant, a timeout, and a fresh `run_id`. The runner materializes a separate
effective workspace, starts a native thread in its persistent private profile,
and stores the native thread ID plus raw event stream under that `run_id`.
The first turn must make an observed tool call with a matching result; capture
its post-run workspace hash and snapshot. Restart the app-server and resume
the same thread only after restoring that exact post-run snapshot. Project
the raw trace into a normalized view and import the rollout into AGENTVIZ,
preserving native IDs and labeling offered versus observed skill use. A
Langflow custom component may then invoke this same runner and carry
structured `run_id` and native ID fields, with outer and inner usage separate.

This pilot proves execution, persistence, and inspection for **one local
Codex run**. It does not require automated skill editing or Claude. The next
slice adds a pinned draft and policy, observed agent-originated denial, patch,
deterministic validation, fixed case, conflict-safe review and promotion.
Only after a supported #121 run should the same contract be tested for
Claude. A client that merely stores flow definitions while a separate host
holds the runner profile, credential, snapshots, native sessions, and raw
traces is the remote-only variant; no current local result proves it.

## Revised estimate and decision gates

The original [proposal](../components/agent-and-skill-components.md) estimated
4-7 engineer-weeks for a single-user local MVP and 8-12 weeks for a robust
multi-user product. Its lower bound assumed the final-response bridge could
be adapted cleanly; #118 showed that bridge uses the personal profile and
does not expose the required native evidence. The estimate also preceded
#146's Docker boundary and #123's trace gap.

For one engineer familiar with Python, Langflow, and the existing code, a
planning range is **6-10 engineer-weeks** for a reviewed single-user Codex
pilot with whole-skill revisions, a pinned Docker runner, snapshot registry,
trace intake, a Langflow node, and basic tests. This includes integration and
hardening time, not model usage, UI design, or production auth. Automated
Skill Draft editing and conflict-safe promotion add a provisional **2-4
weeks** after the pilot, using #122's core and #146's boundary. A second
Claude provider adds an estimated **3-6 weeks after #121 is unblocked**;
the range is provisional because effort, skill isolation, and streamed events
have no local model-backed result. Thus the original two-provider local scope
is roughly **11-20 engineer-weeks**, with the Claude portion the least
certain. A hosted or multi-user product cannot be
estimated responsibly from these spikes as a fixed 8-12-week commitment;
authentication, tenancy, data retention, remote operations, and licensing
remain unscoped. Re-estimate it after #129 and a remote pilot design.

| Local Codex pilot work package | Planning days |
| --- | ---: |
| Pinned Docker runner, private profile, grants, and snapshot registry | 7-11 |
| Whole-skill revision storage and exact materialization | 5-8 |
| Raw trace intake, ID correlation, and AGENTVIZ inspection path | 5-8 |
| Typed Langflow component and structured flow handoff | 3-5 |
| Integration, failure tests, review, and hardening | 8-12 |
| Version and environment contingency | 2-6 |
| **Total** | **30-50 days, about 6-10 engineer-weeks** |

The next implementation proposal should use these gates, in order:

1. **Local Codex execution:** selected model/effort reported effectively;
   private profile remains separate; one observed tool call/result; failure
   and timeout retain partial trace; resume restores the exact last post-run
   snapshot. Any miss is a no-go for the local pilot.
2. **Skill boundary:** exact revision and grant are pinned; only the draft is
   writable; synthetic forbidden paths and symlink escapes are denied with
   observed agent events; validation and a fixed case pass before a separate
   reviewed promotion. Any unknown filesystem boundary is a no-go for
   automated editing.
3. **Trace correlation:** Langflow invocation, Laomedo run, native session,
   and workspace refs are structured and queryable; raw events survive
   projection changes; unknown, unsupported, omitted, and zero stay distinct.
4. **Second provider:** Claude meets the same five predeclared #121 conditions
   with a supported credential and a reviewable licensing position. Until
   then, the dual-provider claim is no-go.
5. **Hosted release:** #129's credential lifecycle, tenant access, rotation,
   revocation, trace redaction, retention, and remote storage boundaries are
   designed and tested. Current local Docker evidence cannot pass this gate.

## Risks, open decisions, and UI baseline

The largest technical risks are auth inheritance, provider version drift,
agent-command escape routes, mismatch between requested and effective grants,
session-to-workspace misbinding on resume, and silently incomplete traces.
Raw prompts, tool outputs, files, and session rollouts can contain sensitive
data. #123 intentionally measured coverage rather than designing governance:
future work must define per-run ownership and read grants, redaction before
export, access to raw versus projected records, retention and deletion,
recovery after partial capture, and audit of who inspected a trace. The
temporary private ChatGPT login must stay outside Git and out of agent tools;
its copied refresh state is not a production identity model. #129 owns its
replacement, and Claude needs its own supported credential mode.

The [open #111 UI-baseline issue](https://github.com/amadou-6e/specs/issues/111)
still names `projects/laomedo/ui`, while the historical AGENTVIZ workshop now
lives under [`deprecated/ui/`](../deprecated/ui/README.md). Recommend a
separate approved issue edit that points #111 to the archived reference and
asks for a new view-owned Laomedo UI specification only when the product flow
is designed. This report does not edit, relabel, or close #111.

The unresolved product choices are whether Langflow remains the sole flow
canvas, whether whole-skill selection is enough for the first pilot, which
runner host owns durable sessions, and when to require Claude parity. None
of the open feasibility issues or this report authorizes production rollout.
