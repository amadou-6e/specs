# Ray trials and process boundaries

Source baseline: [`theseo-anysearch` fd94554c](https://github.com/amadou-6e/theseo-anysearch/tree/fd94554c9620096f94aaed95ffda6a1bbd4711ec), inspected 2026-09-28. Tests at this revision were read, not run; source wiring is not proof of remote portability.

## Experiment Tune process boundary

The experiment sweep uses a module-level function trainable intended for Ray serialization. The driver resolves output and input paths and passes a JSON-mode `ExperimentConfig` dictionary plus sampled settings to the trial; the trial reconstructs typed configuration, applies algorithm/model samples, and creates its own trial directory. This describes source wiring, not verified remote portability. See [trainable configuration](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L326-L406) and [driver parameterization](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L1375-L1397).

The driver reads custom metric, reward, scenario, geometry and imitation source contents and a native extension manifest/binary, then passes them as fixed Tune parameters. Each trial writes the sources and native files under its own directory before `Trainer.from_settings`, so availability on the driver alone is not the intended loading contract. The inspected tests do not establish loading on another machine or remote filesystem. See [source materialization](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L290-L321), [trial setup](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L408-L530), and [driver collection](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L1122-L1209).

Ray's Tune bookkeeping is separate from the trial's training artifacts. The former defaults to a short system-temporary `anysearch_tune` directory and can be overridden with `ray_storage_dir`; the latter lives beneath the experiment output directory. `--resume-tune` requires restorable Ray storage and restores unfinished/errored trials, while `--extra-trials` creates a new continuation segment rather than restoring missing Ray state. A trial artifact directory alone is therefore insufficient for Tune resume. See [storage and continuation setup](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L1238-L1317) and [Tuner creation/restore](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L1473-L1506).

The trainable applies `with_resources` to the base function **before** `with_parameters`; a source comment reports that reversing this order silently drops the placement group in the Ray version used there. Trials set `reuse_actors=False` to avoid stale bundle references. Neither the comment nor the configuration proves actual placement or isolation. See [resource/wrapper setup](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L1334-L1397) and [Tuner configuration](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L1483-L1505). Requested bundle accounting belongs in [resources and placement](resources-and-placement.md).

During training, the trial writes status/history, reports metrics and periodic checkpoints to Tune, closes its MLflow child run, and stops a constructed RLlib algorithm in `finally`. **Cleanup has a pre-training gap:** `Trainer.from_settings` and checkpoint restoration precede the `try` around `trainer.train`; a construction or restore exception bypasses that status/MLflow/algorithm cleanup block. The driver separately records sweep status and conditionally shuts down Ray after its own Tuner block. Actor reclamation after abnormal trial failure has not been verified. See [trial reporting and cleanup](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L530-L610) and [driver status/finally](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L1519-L1580). Initialization ownership and shutdown policy are covered in [runtime lifecycle](runtime-lifecycle.md).

On Windows, this path patches Ray's private `_atomic_save` to normalize mixed separators and report `MAX_PATH` errors. It handles patch-installation exceptions, but effectiveness across Ray versions is unverified. See [patch implementation and call](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L618-L671) and [installation site](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/experiments/tune_runner.py#L1402-L1402).

## Other Tune entry points

The [model-garden Tune runner](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/garden/tune_runner.py#L72-L201) has a separate `GardenConfig`/pretraining trainable and simple CPU/GPU resource request; do not infer the experiment runner's source materialization or MLflow behavior from it. The [deprecated `anysearch tune` CLI](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/theseo_anysearch/cli/commands/tune.py#L965-L1114) has separate path/trainable handling and unconditional Ray shutdown. These are distinct process-boundary contracts, not aliases for the experiment sweep.

## Evidence and open checks

The inspected [Tune integration tests](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/tests/test_rllib/test_integration/test_tune_runner_ray.py#L259-L555) include mocked reporting/trainer checks, local serialization checks, and declared live sweeps; they were **read, not run** for this page. The [resource unit test](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/tests/test_rllib/test_unit/test_tune_runner_resources.py#L314-L335) checks the `reuse_actors` argument, not actor reuse in a cluster. A [custom-scenario helper test](https://github.com/amadou-6e/theseo-anysearch/blob/fd94554c9620096f94aaed95ffda6a1bbd4711ec/tests/test_experiments/test_unit/test_custom_scenarios.py#L70-L87) writes `scenarios.py` but does not prove remote loading. Verify remote extension loading, construction-failure cleanup, cancellation, and trial isolation before claiming portability. Upstream Ray internals, CI history, and live-cluster behavior were not inspected. Training-result semantics belong to the training-and-tuning subsystem.
