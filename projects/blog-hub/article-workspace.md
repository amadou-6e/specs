# Article Workspace

Every article lives in its own directory under `data/articles/<article-id>/`.
The agent (Claude or Codex CLI inside the runner) receives the workspace root as its working directory for any editing task.

---

## Directory layout

```
data/
  articles/
    art_6f2ce277/
      article.md              ← canonical content, current version
      meta.json               ← structured metadata (see below)

      history/
        v001.md               ← immutable snapshot written before each accepted change
        v002.md
        patches/
          p001.json           ← diff, source (ai|manual), comment_ids, accepted_at
          p002.json

      context/
        docs/
          brief.md            ← original author brief (new-article path only)
          ref-doc.pdf         ← uploaded reference documents
        urls/
          example-com.md      ← crawled page as clean markdown
          example-com.meta.json   ← { url, title, crawled_at }
        search/
          query-slug.md       ← formatted search result summaries
          query-slug.meta.json    ← { query, searched_at, result_count }

      assets/
        images/
          hero.png            ← uploaded or generated image
          hero.prompt.md      ← generation prompt or description
          hero.meta.json      ← { source: "generated"|"uploaded", model, alt, created_at }

      skills/
        skill.md              ← copy of the selected skill template (frozen at creation)

      prompts/
        system-prompt.md      ← assembled agent system prompt (frozen at creation)
        generation.md         ← full prompt sent to the AI to create the article
        edits/
          20260406-150012-fix-intro.md   ← edit instruction applied by agent
          20260406-160045-add-table.md
```

Global skill templates live in `blog-hub/skills/` and are copied into the workspace at creation time:

```
blog-hub/
  skills/
    deep-dive.md
    tutorial.md
    comparison.md
    opinion.md
```

## meta.json shape

```json
{
  "id":         "art_6f2ce277",
  "title":      "A Practical Intro to pgvector",
  "version":    3,
  "source":     "generated",
  "word_count": 1420,
  "gate":       "pass",
  "created_at": "2026-04-06T09:00:00Z",
  "updated_at": "2026-04-06T15:00:00Z",
  "destinations": {
    "medium": { "status": "draft_created", "url": "https://medium.com/..." }
  }
}
```

`source` is one of `"generated"` | `"uploaded"` | `"imported"`.

---

## Versioning rules

- A snapshot (`history/vNNN.md`) is written **before** every accepted change.
- Patches are always diff-based (`history/patches/pNNN.json`). No silent full overwrites.
- `article.md` is always the current canonical content. Agents read and write this file.
- Version numbers are zero-padded to 3 digits (`v001`, `v002`, …).

---

## Context rules

| Type | Written when | Read by agent |
|------|--------------|---------------|
| `context/docs/brief.md` | Article created via new-article path | Yes — part of the article's original intent |
| `context/docs/<file>` | User uploads reference document | Yes — provides background |
| `context/urls/<slug>.md` | URL linked or web search enabled | Yes — crawled content |
| `context/search/<slug>.md` | Web search enabled | Yes — search summaries |

Existing-content articles (`source: uploaded | imported`) have no `context/docs/brief.md`.
Their `context/` starts empty unless the user adds references later in the editor.

---

## Asset rules

- Every image has a paired `.prompt.md` and `.meta.json`.
- Images generated by the agent use the prompt file as the source of truth for regeneration.
- Uploaded images have an empty `.prompt.md` (user may fill it in).
- `article.md` references images with relative paths: `![alt](assets/images/hero.png)`.

## Skills

A skill defines the article's structural contract: section order, tone, formatting rules, and what the agent must include or avoid. Skills are selected once during article creation and frozen into the workspace. The editor can display the skill but does not let the user swap it after creation.

| Skill | Purpose |
|-------|---------|
| `deep-dive` | Technical depth, concrete examples, edge cases, real-world usage |
| `tutorial` | Step-by-step, prerequisites, verification checks, common pitfalls |
| `comparison` | Setup complexity, perf, DX, ecosystem, summary table, recommendation |
| `opinion` | Clear thesis, evidence, counterarguments, takeaway |

`skills/skill.md` is the frozen copy. It is the primary style reference for the agent during every edit session.

---

## System prompt assembly

`prompts/system-prompt.md` is assembled once at article creation and never modified. It is passed verbatim to the agent as the system prompt for every editing task on this article.

Assembly order:

1. **Base role** — fixed preamble defining the agent as a technical writer
2. **Skill template** — full contents of `skills/skill.md`
3. **Workspace map** — paths the agent may read/write
4. **Constraints** — word count target, image reference format, edit log rule

The backend assembles and writes this file when `store.create_workspace()` is called.

---

## Agent access

When the runner executes an editing task, it receives:

```
ARTICLE_WORKSPACE=/workspace/data/articles/<article-id>
```

The agent is expected to:
1. Read `prompts/system-prompt.md` as its operating instructions.
2. Read `article.md` as the document to edit.
3. Read any files under `context/` and `skills/` for background and style.
4. Write its changes back to `article.md`.
5. Append a timestamped file to `prompts/edits/` with the edit instruction used.
6. NOT touch `history/` — the backend writes snapshots before calling the agent.

---

## Docker mount

`data/` is bind-mounted into the runner container so the agent can read and write workspaces:

```yaml
# docker-compose.yml (cli-runner service)
volumes:
  - ./data:/workspace/data
```

The runner sets `ARTICLE_WORKSPACE` before spawning the agent process.

---

## Editor handoff

After article creation (both paths), the backend returns `{ id, title }`.
The frontend navigates to:

```
/screens/editor/v1.html?id=<article-id>
```

The editor loads `GET /api/articles/<id>` for metadata and `GET /api/articles/<id>/content` for the markdown body. It does not read the workspace files directly — only the agent and backend do.
